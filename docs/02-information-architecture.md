# 公司级信息架构与业务域边界

## 1. 信息架构

公司工作台的顶层导航只表达通用管理任务：

1. 公司总览：通用任务、审批、已完成事项、已接入域和运行提示。
2. 任务中心：跨域统一 DAG 任务。
3. 审批中心：跨域结构化写入门禁。
4. 项目空间：跨域上下文容器，不复制域数据。
5. 知识与文件：公司知识、来源、文件和产物能力。
6. 业务域：展示插件贡献的域入口和工作流。
7. 审计记录：按公司、域、项目、任务和操作者追溯。
8. 平台设置：模型、搜索、调度、本地运行和身份边界。

销售客户、商机、拜访、行动和投标不能成为公司首页固定导航。第一阶段首页的“业务域工作”快捷项只由当前 Profile 已启用的工作流动态填充；已安装但未启用的域在业务域页明确显示为候选，不能发起任务。

## 2. 业务域边界

| 范围 | 负责 | 明确不负责 |
| --- | --- | --- |
| 平台本体 | 插件发现、Profile 组合、任务、审批、审计、权限收敛、项目作用域、模型/搜索/文件/PPT/调度适配器、桌面生命周期 | 客户、商机、销售活动、投标等域对象 |
| 销售域 | 客户与机会事实、管道复盘、销售行动、资源协调及销售专用页面/流程/技能/存储 | 公司角色、插件治理、模型提供方和审计策略 |
| 项目空间 | 项目 ID、名称、状态、成员范围、文件/任务/域对象链接 | 复制客户、机会或其他业务域主数据 |
| 公司知识库 | 来源、证据、访问范围、域/项目关联和审批写入 | 任意业务域绕过审批的公共写入后门 |

## 3. 插件贡献点

第一阶段采用本地受控静态注册，不执行远程插件 JavaScript。插件可以贡献：

- 业务域名称、说明、版本和状态。
- 能力、工具 `effect: read|write`、权限与显式 `write_permissions` 声明。
- 受控工作流 JSON。
- Pi Skill 标识；当前 Profile 启用某业务域时，启动器按该域清单通用解析 Skill，不在核心写域名特例。
- 域导航分组和顺序。
- 数据作用域要求。

后续可以增加只读 `DomainSummaryProvider`、`DomainSearchProvider`、`DomainReportProvider` 和 `DomainEntityLinkResolver`。共享层只消费统一 DTO，不能直接导入销售存储。

## 4. 页面状态

所有页面需处理：

- 正常：显示当前本机真实任务/审批/插件状态。
- 加载：全屏中文准备提示，不闪现未初始化数据。
- 空状态：说明当前没有事项，并提供安全下一步。
- 禁用：按钮明确说明“后续阶段”或“尚未配置”。
- 错误：中文提示，不暴露密钥、绝对路径或堆栈。
- 超时/服务不可用：保留重试入口，不能伪装为“零数据”。
- 审批冲突：说明任务或载荷已变化，要求刷新并重新核对。

## 5. 交互与防误操作

- 发起任务时只要求工作流、清晰标题和可选项目编号。
- 结构化写入不会在发起任务时立即发生。
- 批准与驳回前显示影响说明；批准按钮不得与普通导航混淆。
- 审批页显示策略、版本、作用域、精确拟执行内容和 payload hash。
- 所有动态文本 HTML 转义，防止业务标题成为脚本或样式注入。
- 键盘焦点可见；使用语义按钮、标签和原生 `dialog`；支持减少动效偏好。
- 正式入口固定为桌面窗口；浏览器模式在文档中标为诊断用途。

## 6. 可插拔性负向约束

1. 默认 `company-manager` 不启用 `domain.sales`。
2. 核心插件 ID 不含销售命名空间。
3. 核心数据库只创建任务、节点、审批和审计表，不创建客户/机会表。
4. 首页指标不读取销售金额、客户或投标表。
5. 销售域不存在时，平台插件注册仍通过。
6. 销售流程只能使用自己清单声明的权限。
7. 公司共享能力不能通过 Profile 字符串判断是否获得销售权限。
8. 平台 CLI、服务提示和 Pi Skill 解析不得硬编码任一业务域 ID、Skill 名或显示文案。
9. 工具是否需要审批由 `effect` 判断；某项权限是否属于结构化写权限由 `write_permissions` 判断，不能从权限名后缀推断。
