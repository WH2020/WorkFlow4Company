# 迁移终态与清理清单

## 1. 终态契约

| 项目 | 已确认终态 |
| --- | --- |
| 变更类型 | 替换：由单角色“销售总监平台”演进为公司级统一管理平台；移除：销售角色作为平台本体、ReqGuard 门禁、第二套任务系统及源项目运行数据。 |
| 替代对象 | 源项目的单角色产品定位、`market/sales` 顶层结构、销售专用默认入口、销售命名的桌面壳与运行目录。 |
| 最终状态 | 独立 Git 项目；轻本体只负责统一导航、插件发现、权限、受控 DAG、审批、审计与能力接入；业务能力位于可插拔域；销售是首个域且可独立启停。 |
| 禁止残留 | 源 `.git`、远端 URL、真实业务数据、用户配置、密钥、任务/审批/审计记录、输入输出、日志、数据库、缓存、浏览器 Profile、依赖目录、安装包；`docs/reqguard`；`@juicesharp/rpiv-todo`；以销售总监作为平台身份的默认值和入口。 |

| 兼容策略 | 新项目不继承运行数据、用户配置或 Git 历史；插件清单采用新命名空间，源配置不做原位升级。后续数据迁移需单独审批、映射与审计。 |
| 清理表面 | 代码、清单、默认配置、桌面标题、脚本、测试、文档、示例、忽略规则、Git 配置和构建产物。 |
| 验证 | 正向验证公司工作台、插件加载、DAG/审批/审计和销售域流程；负向扫描禁止路径、包名、凭据模式、旧产品级标识、远端配置及 ReqGuard 目录。 |

## 2. 保留、改造、删除

### 保留并复用

- 插件清单驱动的轻本体、依赖校验和受控 DAG 思路。
- Pi 主智能核心的扩展入口和技能目录约定。
- 结构化写入必须经过审批、每步留审计事件的运行原则。
- 模型接入、聚合搜索、知识库、项目空间、文件处理、演示文稿、定时任务作为公司级共享能力插件。
- Tauri 2 + 本地工作台 + Pi 核心的桌面应用路线。
- 可公开复用的契约、空模板、合成测试和通用文档结构。

### 改造后迁移

- `sales-director` Profile 改为 `company-manager`，只选择业务域而不定义平台本体。
- `market.sales` 改为 `domain.sales`，销售数据权限限制在销售域和项目空间。
- 销售管道复盘改为首个插件验收流程，仍使用统一 DAG、任务、审批和审计表。
- 产品名、窗口标题、可执行文件、日志目录、健康检查和安装脚本统一改为 Agent4Company/公司管理平台。
- 源模型、搜索、知识、文件、PPT 和调度能力从销售语境抽出，先以共享能力契约和状态接口接入；具体供应商由后续配置决定。

### 不迁移或删除

- `.git/`、源远端、分支、worktree、提交历史。
- `.pi/`、`.tmp/`、`tmp/`、`runtime/`、`node_modules/`、`dist/`、Tauri `target/` 和 `gen/`。
- `data/` 中非 `*.example.*` 或 `.gitkeep` 内容、`inputs/` 实际文件、`outputs/`、数据库及 WAL/SHM、日志、安装包。
- `.env*`、密钥证书、用户 Profile、模型账号配置、本地模板目录、浏览器 Profile 和访问令牌。
- 源项目的 WeFlow/邮件报销等用户绑定集成；需要时作为独立插件重新评审。
- ReqGuard 代码或 `docs/reqguard` 门禁目录。
- `@juicesharp/rpiv-todo` 及任何与 DAG/任务/审批并行的第二事实源。

## 3. 防回流规则

1. 根目录 `.gitignore` 默认拒绝凭据、运行数据、数据库、日志、依赖和安装产物。
2. `tests/test_repository_hygiene.py` 检查禁止目录、包名、源远端和旧产品级默认标识。
3. 销售域只能通过插件注册表暴露；平台导航和核心运行时不得导入销售专用存储。
4. 历史名称只允许出现在本迁移记录和产品文档的来源说明中。
5. 新增结构化写入节点必须具有一个直接审批前驱，并写入统一审计表。
