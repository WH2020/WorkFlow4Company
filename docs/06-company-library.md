# 公司资料库模块设计与第一版实现边界

## 1. 产品定位

公司资料库是公司管理平台的一个公司级共享能力，不属于销售域，也不复制一套任务或审批系统。

当前产品条件是：初创公司、单一使用者、资料量较小，主要资料为 BP、专利和开发文档。因此第一版选择“可靠的本机文件柜 + 可追溯版本 + 证据检索”，不提前建设多人文档协作、复杂权限矩阵或向量数据库。

### 目标用户与场景

唯一目标用户是公司创始人/本机管理员，典型任务包括：

1. 导入一份 BP、专利或开发文档，并标明类型、密级和标签。
2. 找到某个主题出现在哪份资料、哪个版本和哪段正文中。
3. 上传新版本，同时保留旧版本供追溯。
4. 必要时把旧版本重新设为当前版本。
5. 归档已经不常使用的资料，但不永久删除历史。
6. 让 Agent 基于资料回答问题，并给出可核验的来源。

### 第一版成功标准

- 首次启动为空资料库，不附带任何源项目或用户资料。
- 支持导入、列表、分类、搜索、预览、下载、版本、归档和恢复的完整本机链路。
- 同一资料的历史版本不可原地覆盖；每版绑定 SHA-256。
- 搜索结果至少包含资料、版本、原文件名和正文片段，不能只返回无出处结论。
- 专利默认“高度保密”，BP 默认“保密”，开发文档默认“内部”。
- 所有成功的资料变更与审计事件在同一 SQLite 事务提交；不新增平行审计事实源。
- 不支持的文件、伪装文件、超限文件和路径型文件名被拒绝，且不会进入正式资料区。
- 模型和公开搜索未配置时，资料库仍能完全在本机工作。

## 2. 范围与非目标

### 必须实现

- 四类资料：`BP`、`专利`、`开发文档`、`公司通用`。
- 三档密级：`内部`、`保密`、`高度保密`。
- PDF、Word、PowerPoint、Excel、Markdown、纯文本、CSV、JSON 的受控导入。
- 本地元数据、内容寻址原文件、不可变版本和当前版本指针。
- 标题、标签、文件名和可抽取正文的本地检索。
- 可抽取正文预览；不能抽取时显示安全降级说明，原文件仍可下载。
- 归档与恢复；不提供永久删除入口。
- 单人模式下的显式本人确认：历史版本切换、归档和恢复均需二次确认。
- 统一审计：导入、新版本、切换当前版本、归档和恢复。

### 建议实现但可延期

- OCR 和扫描版 PDF 识别。
- 文档间引用关系、专题合集和时间线。
- BP/专利/开发文档专属字段模板。
- 本地向量索引和混合检索；只有关键词检索明显不足时再引入。
- 批量导入、重复文件整理建议和自动标签。

### 明确不做

- 不做多人实时协作、评论、在线编辑或企业 SSO。
- 不做 Dropbox、Google Drive、网盘或对象存储同步。
- 不自动把 BP、专利或开发文档发送给外部模型。
- 不向模型提供归档、改密级、切换版本或删除能力。
- 不提供公开分享链接、邮件外发或永久删除。
- 不引入第二套 Todo、审批或审计系统。
- 不把销售资料结构放进平台内核；未来销售资料通过引用关联本模块。

## 3. 信息架构与交互

资料库页面采用三栏布局：

```text
资料范围              资料列表                     资料详情
├─ 全部资料            ├─ 搜索 / 排序                ├─ 名称、类型、密级
├─ BP                  ├─ 命中片段                   ├─ 当前版本与哈希
├─ 专利                ├─ 当前版本 / 更新时间         ├─ 正文预览与证据位置
├─ 开发文档            └─ 归档状态                   ├─ 下载 / 上传新版本
├─ 公司通用                                         └─ 历史版本 / 归档恢复
└─ 已归档
```

### 导入流程

```text
选择文件
→ 填写或确认标题、类型、密级、标签、版本说明
→ 检查大小、文件名、扩展名、文件特征和容器结构
→ 计算 SHA-256
→ 原子写入内容寻址 Blob
→ 抽取可检索正文（失败时安全降级）
→ 在 SQLite 事务中创建资料与首个不可变版本
→ 写入统一审计事件
→ 在详情页打开新资料
```

### 新版本流程

新版本必须关联现有资料。导入成功后增加版本号并成为当前版本，旧版本与旧 Blob 不修改。若上传内容与当前版本完全相同，应拒绝重复版本，避免制造无意义历史。

历史版本重新设为当前版本时，界面展示目标版本、文件名和哈希，并要求本人二次确认。该操作只切换指针，不复制或覆盖 Blob。

### 空、失败与降级状态

- 空资料库：说明支持的资料类型并提供“导入第一份资料”。
- 无搜索结果：保留筛选条件，提示调整关键词或资料范围。
- 正文不可抽取：显示文件仍已安全保存、可下载查看；不能伪装成已经完成正文索引。
- 文件被拒绝：显示具体原因，不创建资料、版本或正式 Blob。
- 审计写入失败：资料变更应回报失败，不能宣称已经完整留痕。
- 数据库事务失败时不在线删除已经激活的内容寻址 Blob，避免与另一笔同内容导入发生竞态；该 Blob 不可从资料库访问，未来只能在停止写入并取得全局独占锁后做离线孤儿回收。

## 4. 数据模型

### `library_items`

| 字段 | 含义 |
| --- | --- |
| `item_id` | 稳定资料 ID |
| `company_id` | 公司作用域，第一版固定 `company-local` |
| `title` | 用户可读名称 |
| `category` | `bp/patent/development/general` |
| `confidentiality` | `internal/confidential/highly_confidential` |
| `tags_json` | 去重后的标签数组 |
| `current_version_id` | 当前版本指针 |
| `status` | `current/archived`；此处表示资料是否在当前列表，不代表版本状态 |
| `created_at/updated_at/archived_at` | 生命周期时间 |

### `library_versions`

| 字段 | 含义 |
| --- | --- |
| `version_id` | 不可变版本 ID |
| `item_id` | 所属资料 |
| `version_number` | 资料内单调递增版本号 |
| `original_filename` | 去路径后的原文件名 |
| `extension/media_type` | 已核验格式 |
| `size_bytes` | 原文件大小 |
| `sha256` | 内容完整性与 Blob 地址 |
| `extracted_text` | 本机检索文本；抽取失败时为空 |
| `extraction_status` | `ready/unavailable/failed` |
| `version_note` | 版本说明 |
| `created_by/created_at` | 导入者与时间 |

Blob 路径采用 `blobs/<sha256 前两位>/<sha256 第 3–4 位>/<完整 sha256>`。相同内容可以共享 Blob，但版本记录保持独立。数据库和 Blob 全部位于 `runtime/`，由 Git 忽略；仓库只提交代码、测试和文档。

## 5. 检索与 Agent 边界

第一版使用 SQLite 本地全文索引；环境不支持 FTS 时回退到受限 `LIKE` 检索。资料量小，不引入独立搜索服务。

检索范围包括：

- 资料标题
- 标签
- 原文件名
- 当前版本可抽取正文

每个证据结果至少返回：

```text
资料 ID + 资料标题
版本 ID + 版本号
原文件名
正文命中片段
SHA-256
```

Agent 第一版仅获得只读检索结果，不直接读取整个 Blob，也不能执行导入、下载、归档、改密级或版本切换。若后续接入外部模型，BP/专利/高度保密资料默认禁止发送；任何例外都必须展示提供方、拟发送片段、目的和保留策略，并由本人逐次确认。

## 6. 安全、审批与审计边界

### 文件安全

- 只接受明确允许的扩展名，不接受可执行文件、脚本、宏启用 Office 文件或压缩包。
- 文件名必须是纯文件名，拒绝绝对路径、目录分隔符、空字节和路径穿越。
- 校验扩展名与文件签名/容器结构，不能只相信浏览器 MIME。
- Office 容器拒绝宏、ActiveX、嵌入对象、外部模板和外部资源；仅保留 `http/https/mailto` 普通超链接，而且导入与预览不会自动访问链接。该机制仍是受控格式校验，不等同于通用恶意文档净化或杀毒扫描。
- 单文件上限 50 MB；压缩容器抽取还限制成员数量、单成员大小和总解压大小，防止压缩炸弹。
- 正式 Blob 只通过临时文件完成校验后原子激活。
- 事务回滚不立即清理共享 CAS Blob；“不可见孤儿优先于误删已被并发事务采用的文件”。第一版不提供在线 Blob GC。
- 下载前重新核对 Blob 路径和 SHA-256；发现内容漂移时拒绝返回。

### 单人确认模型

当前只有一个本机管理员，不伪装成已经实现职责分离。普通导入和新增版本由用户主动提交并记审计；历史版本切换、归档和恢复要求显式二次确认，而且确认约束同时位于核心 Store 和 HTTP 接口。此处“本人确认”是单人本机界面的操作确认，不是第二身份、电子签名或职责分离证明。永久删除和外发第一版没有入口。

业务域结构化写入仍必须使用原有受控 DAG 和 Approval。资料库的人机直接操作不会创建第二套 DAG 任务；其写操作通过同一 `audit_events` 表追加记录 `actor_id=local-admin`、动作、结果、资料/版本 ID 和内容哈希。

第一版统一审计记录已接受并提交的资料变更；格式校验失败、缺少确认等被拒请求只返回错误并进入本地 HTTP 运行日志，不持久化为安全审计事件。引入第二位使用者或远程访问前，应把拒绝/失败尝试纳入独立的安全事件策略，同时避免将敏感原文写入日志。

## 7. API 边界

所有写接口仍要求本机 Host 和 `X-Company-Session`。建议接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/library` | 概况、筛选后的资料列表 |
| GET | `/api/library/items/<id>` | 资料详情、当前预览和版本历史 |
| GET | `/api/library?q=...` | 本地证据检索；与状态、分类、排序筛选共用列表接口 |
| GET | `/api/library/versions/<id>/content` | 校验后下载原文件 |
| POST | `/api/library/import` | `multipart/form-data` 导入首版或新版本 |
| POST | `/api/library/items/<id>/current` | 本人确认后切换当前版本 |
| POST | `/api/library/items/<id>/archive` | 本人确认后归档 |
| POST | `/api/library/items/<id>/restore` | 本人确认后恢复 |

正文和文件上传使用独立大小限制；现有普通 JSON 请求的 64 KB 限制不放宽。上传解析设 30 秒连接超时并在进程内串行执行，避免多个 50 MB Office/PDF 同时抽取；当前实现仍会把单个上传与抽取内容放入内存，不是面向不可信多用户的上传服务。

## 8. 验收与测试

### 正常路径

- 分别导入合成 BP、专利和开发文档，默认密级正确。
- 中文标题、标签和正文可检索，结果带版本和证据片段。
- 上传第二版后旧版仍可读取，当前版本指向新版。
- 切回历史版本后 Blob 未变化，审计记录目标版本和哈希。
- 归档资料从默认列表消失，在“已归档”中可恢复。
- 下载字节与导入字节完全一致。

### 负向与边界

- 拒绝路径穿越文件名、绝对路径、空文件、超限文件和不支持后缀。
- 拒绝扩展名与文件特征不匹配、伪装可执行文件和危险 Office 容器。
- 拒绝给不存在的资料添加版本、切换到其他资料的版本和缺少确认字段的敏感操作。
- Blob 被篡改后下载失败，不返回损坏内容。
- 重复同一当前内容不创建新版本。
- 未携带会话令牌的写请求返回拒绝。
- 仓库跟踪文件中没有资料数据库、Blob、输入输出、日志或真实业务文件。

## 9. 后续演进触发条件

只有出现明确需求时再扩展：

- 第二位长期使用者出现：引入真实身份、角色、资料访问范围和职责分离。
- 资料规模增长且关键词检索不足：评估本地向量索引与混合召回，并建立检索评测集。
- 需要团队共享：先确定本地局域网或云端托管、加密、备份、权限和冲突模型，不直接把当前 SQLite 暴露为网络服务。
- 需要外部模型分析：建立逐次披露确认、脱敏、提供方策略和外发审计。
- 需要永久删除：设计保留期、Blob 引用计数、备份清理和可恢复窗口后再开放。
